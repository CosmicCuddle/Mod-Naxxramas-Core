## New material source distinctions

| Source-backed behavior | Pinned native code | Consequence for a future trusted F15 collector |
| --- | --- | --- |
| **Worldserver async logging is CONFIG-conditional.** It creates an `IoContext` and passes it into `sLog->Initialize` only if `Log.Async.Enable` is true (default fallback false). Public `.conf.dist` says `Log.Async.Enable=0`. | `src/server/apps/worldserver/Main.cpp:189–194` and `worldserver.conf.dist:815–820` | Never assume async mode from public source alone. If enabled, `Log::write` posts work to the I/O context and returns **without a durable acknowledgement**; abrupt process death can leave pending logging tasks unwritten. This is a possible loss pathway, not a witnessed crash/lost log. |
| **Authserver uses synchronous logger initialization in this pinned Main.** `sLog->Initialize(nullptr)` even though it separately starts a networking `IoContext`. | `src/server/apps/authserver/Main.cpp:89–92,137` | Do not apply the Worldserver async logger assumption to Authserver; effective installed custom build must still be independently checked. Synchronous call is NOT disk durability. |
| **Source routing differs by level.** Console routes ERROR/FATAL to stderr, other levels including WARN to stdout. | `src/common/Logging/AppenderConsole.cpp:172–212` | stderr/stdout origin is only a hint, not a reliable parsed severity or guaranteed record delivery. |
| **Severity prefix is conditional, and the two PUBLIC sample console appenders use flags=0.** Appender only prints level text when `APPENDER_FLAGS_PREFIX_LOGLEVEL` bit is set. | `src/common/Logging/Appender.cpp:53–79`, Worldserver `Appender.Console=1,4,0,...`, Authserver `Appender.Console=1,5,0,...` | Cannot auto-classify WARNING/ERROR/FATAL from unprefixed console bytes. F15 canonical severity must remain `unknown` unless independently verified declared prefix/config, not inferred from stderr alone. |
| **Files open in overwrite mode by default in both PUBLIC templates.** World `Server.log`, `Playerbots.log`, `Errors.log`, and Auth `Auth.log` explicitly use `,w`. The file appender calls `OpenFile(_fileName, mode, ...)` at startup, using `fopen(..., mode)`. | `AppenderFile.cpp:25–76, 122–139`; public `.conf.dist` file appender settings | New process startup can truncate previous active log before an external late-starting tailer reads it. No claim owner's installed setup uses these defaults. A safe tailer needs pre-restart capture, inode/offset/rotation tracking, and a restore/retention plan. |
| **File rotation and dynamic filenames**. At configured max size, static file appender calls `OpenFile(...,'w',true)`; backup uses `rename`, ignores result. Dynamic `%s` names open in append mode and may be backed up. | `AppenderFile.cpp:84–150` | A pathname is not an immutable stream. Follow inode/identity and detect replacement/rotation, but don't take destructive recovery or open any actual owner file without permission. Filename changes can cause gaps or duplicates. |
| **Appenders can drop file output without raising a per-message durable receipt.** `OpenFile` can return `nullptr`; write branch returns; file output uses `fprintf`/`fflush` but no `fsync`/`fdatasync`. | `AppenderFile.cpp:84–142` | No complete, crash-safe, authenticated guarantee that every generated message entered a file or stayed on disk. `fflush` is not equivalent to filesystem sync. F15 must label missing or dropped stream tails as **incomplete / unknown**, not assert no WARN/ERROR occurred. |
| **Logger + appender are two distinct filters and fallbacks matter.** `Logger::write` checks logger level/text, `Appender::write` separately filters level, `Log::ReadLoggersFromConfig` may `Close()` and fall back to root/server **console-only** if no root logger exists. | `Logger.cpp:49–62`, `Appender.cpp:53–79`, `Log.cpp:186–224` | A selected output route can omit messages before a collector ever sees them. Lack of a file/WARN is not absence of event, and presence of an Errors appender entry does not by itself mean every server error is routed to it. |
| **Worldserver shutdown turns logging synchronous after stopping its IO worker pool.** | `worldserver/Main.cpp:413–425`, `Log.cpp:244–255` | A shutdown/cancellation boundary exists; source alone doesn't attest drain of outstanding posted log tasks. Treat planned exit, shutdown and lost tail separately. |

## Safety contract before a selected observer is proposed

1. **Route fidelity:** only attested process/source stream and positively declared prefix become severity; unprefixed logs remain unknown. No FATAL-from-stderr, no `exit 139` → SIGSEGV conversion.
2. **Completeness is limited:** record observed bytes and source lifecycle. An async logger, rotating/truncated file, filtered messages, source-after-start, `fflush` without fsync or missed journal events can leave gaps. Do not assert *no errors* because a collector saw none.
3. **No silently destructive tailing:** never change file open mode, take over process stdin, replace existing launcher, rename/rotate owner's active logs, run real binaries, or edit logger configuration merely to suit F15.
4. **Independent daemon policies:** World/Auth may have different logger buffering/launcher/coredump behaviours; both must meet crash and warning/error requirements before F15 can be considered operational.
5. **Canonical events versus burst semantics:** Existing [#183](https://github.com/CosmicCuddle/Mod-Naxxramas-Core/pull/183) proves nonzero exits are not automatically fatal crashes; one declared WARN/ERROR line is not a qualifying S4b burst. Do not invent per-line timestamp, category or sequence from the canonical schema.
